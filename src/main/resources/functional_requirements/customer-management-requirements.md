# Customer Management API - Functional Requirements

Overview

We will build a Java-based REST API to manage customers. The API will provide full CRUD operations with support for pagination, sorting, and searching. Input validation and JWT-based authentication will be required. The service will publish an OpenAPI specification and include unit and integration tests.

Functional Requirements

1. Customer Entity
   - Fields:
     - id: UUID (generated by server)
     - firstName: string (required)
     - lastName: string (required)
     - email: string (required, valid email format, unique)
     - phone: string (optional, validated if present)
     - status: enum [ACTIVE, INACTIVE, SUSPENDED] (default: ACTIVE)
     - createdAt: timestamp (auto-generated)
     - updatedAt: timestamp (auto-updated)

2. Endpoints
   - POST /api/customers
     - Create a customer. Validates required fields and uniqueness of email.
   - GET /api/customers/{id}
     - Retrieve a customer by id.
   - GET /api/customers
     - List customers with pagination (page, size), sorting (sortBy, direction), and search (q search across firstName, lastName, email).
   - PUT /api/customers/{id}
     - Update a customer's details (all fields except id, createdAt).
   - DELETE /api/customers/{id}
     - Soft-delete customer (mark status as INACTIVE).

3. Security
   - All endpoints require JWT authentication.
   - Role: USER, ADMIN. Only ADMIN can delete.

4. Validation
   - Proper validation errors with HTTP 400 for bad requests.

5. OpenAPI
   - Auto-generate OpenAPI (Swagger) docs at /swagger-ui.html or /api-docs.

6. Tests
   - Unit tests for services and controllers.
   - Integration tests using in-memory DB.

Non-functional

- Use Spring Boot (recommended) or Micronaut.
- Use a relational DB (H2 for tests, configurable for production).
- Logging and basic metrics.
- Container-friendly (Dockerfile).
