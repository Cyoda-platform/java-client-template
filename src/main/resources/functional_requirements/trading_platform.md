# Real-time Trading Platform — Functional Requirements (MVP)

## Overview
Build a Java-based real-time trading platform supporting equities and derivatives trading with external market data feeds, order management, portfolio tracking, risk controls, and regulatory compliance. The platform target is a public template-generated branch for rapid iteration and testing.

## Scope
- Instruments: Equities, Options (initial), ETFs (optional expand)
- Order types (MVP): Market orders, Limit orders, Stop orders (stop-loss/take-profit)
- Market data: External live feeds (Level 1 quotes, trade ticks, reference data)
- Core features: OMS, PMS, Risk Engine, Market Data Service, Compliance & Reporting
- UI: API-first with an optional basic dashboard for monitoring and trade entry
- Simulator: No internal simulator; integrate with live feeds or external sandbox

## Non-functional requirements
- Latency/Throughput: Near real-time target (10-100ms) with a balanced approach for throughput
- Security: Audit trails, role-based access control, encryption at rest and in transit
- Data retention: Configurable retention for trades and market data; archival workflows

## High-level Components
1. Market Data Ingestion
   - Connect to external feeds (adapters per feed provider)
   - Normalize quotes and trade ticks into canonical message formats
   - Streaming pipeline to distribute to subscribers (order router, risk engine, watchers)

2. Order Management System (OMS)
   - REST + WebSocket APIs for order entry, modification, cancel
   - Order lifecycle: New -> Acknowledged -> PartiallyFilled -> Filled -> Cancelled -> Rejected
   - Execution reports and FIX/adapter integrations optional

3. Portfolio Management System (PMS)
   - Real-time positions, P&L, realized/unrealized calculations
   - Holdings per account, per strategy, and aggregated views

4. Risk Engine
   - Pre-trade checks: credit/exposure, sanctions, size limits, max slippage
   - Real-time risk monitoring: position limits, intraday Greeks for options
   - Post-trade checks: P&L reconciliation, broken trade detection

5. Compliance & Reporting
   - Immutable audit trail for all order actions and market events
   - Trade reporting exports and schedule-based reports
   - Alerts and case management for suspicious activity

## Entities (examples)
- MarketData: symbol, timestamp, bid, ask, last, volume, source
- Order: id, account_id, instrument, type, price, size, status, timestamps
- Execution: exec_id, order_id, price, size, venue, timestamp
- Position: account_id, instrument, quantity, avg_price, pnl
- RiskProfile: account_id, limits (size, exposure), flags
- ComplianceEvent: event_id, type, details, timestamp

## Workflows
- Market data ingest -> normalize -> publish to topics
- Order submit -> pre-trade risk check -> route to venue -> handle execution reports -> update PMS & audit trail
- End-of-day P&L & reconciliation job

## Integration Points
- Market data providers (external adapters)
- Exchanges / brokers (FIX / API adapters)
- Identity & KYC providers for consent and suitability
- External reporting sinks (regulatory endpoints)

## Testing & Environments
- Dev: Local with mocked feed adapters and sample data
- Staging: Connect to test feeds or vendor sandboxes
- Prod: Connect to live feeds with monitoring and alarms
